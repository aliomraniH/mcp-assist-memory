# RESEARCH 2 — Intent-Mediation / Plan-Verification Layer: Prior Art, Protocol Fit, Tiered Architecture
(Generated 2026-07-29 from the deep-research pass; in-folder copy for Claude Code context. Full cited version lives in the chat artifact. This report is the design basis for INTENT_GATE_CHARTER.md — the S-facts in the Claude Code prompt trace here.)

## TL;DR
- Every element of the proposed design has strong prior art. Closest single piece: VIGIL's verify-before-commit loop (arXiv 2601.05755 — Intent Anchor + Speculative Reasoner + Grounding Verifier; SIREN benchmark), on the theoretical backbone of LLM-Modulo (Kambhampati et al., ICML 2024: LLMs generate, sound external verifiers critique). The genuinely novel move is using a provenance-and-reconciliation-backed coordination memory as the external verifier, and retrieving known past failures BY INTENT to push back on the caller.
- **MCP sampling is a dead end for Tier 2**: unsupported in Claude Desktop/Code (issue #1785 — servers needing inference must call provider APIs directly) and deprecated in the 2026-07-28 RC (SEP-2577, annotation-only, ≥12-month grace; new implementations shouldn't adopt). Elicitation (2025-06-18) fits the human clarification loop (primitive-type JSON-Schema requests; growing client support in VS Code/Cursor; talks to the USER, not the calling LLM). Tool annotations (readOnly/destructive/idempotent/openWorld) are a risk vocabulary — hints, not enforcement. SEP-1862 "Tool Resolution" (draft, unmerged) is the protocol-level pre-flight/two-phase pattern; five annotation SEPs draft; no first-party dry-run SEP.
- Evidence mandates a tiered gate: LLM self-critique is weak/net-negative (arXiv 2402.08115 — stacked verification+critique errors make self-critique worse than a single guess; CRITIC ICLR 2024 — gains only with external tool-grounded feedback), and critic loops actively hurt easy/high-confidence tasks (documented 15–40% accuracy drops — the false-positive tax). Deterministic first, similarity second, LLM only for ambiguous/destructive cases.

## Area highlights
1. **Protocol**: elicitation for user clarification; direct provider API (curator path) for server-side reasoning; annotations for confirm-UX; watch SEP-1862. Sampling additionally lacks origin authentication (arXiv 2601.17549).
2. **Critics**: LLM-Modulo + VIGIL as the loop shape; CRITIC for tool-grounded correction; Ask-before-Plan / "Ask or Assume?" / "Knowing When to Ask" — clarification must be uncertainty-gated, not always-on; Drift-Bench's action taxonomy (Ask_Parameter, Disambiguate, Propose_Solution, Confirm_Risk, Report_Blocker) maps to the gate's verdict vocabulary. ASPI (arXiv 2605.17324): seeking clarification amplifies injection exposure — clarify-loop responses are untrusted data.
3. **Intent recognition**: vLLM Semantic Router (ModernBERT intent classification + semantic tool filtering) as the cheap first tier; embedding router with LLM fallback only for ambiguous/out-of-scope; expand router examples from misrouted cases over time.
4. **Preview/dry-run**: WebDreamer (TMLR 2025 — simulate-before-commit, +34.1/42.3/23.8% over reactive baselines; fidelity depends on world-model realism) for the concept; terraform plan / kubectl --dry-run / SQL EXPLAIN as the engineering template. Key insight: for the server's OWN state changes the preview can be deterministic and exact (diff, supersession, lineage impact) — sidestepping world-model fidelity entirely. Scope previews to what the server computes deterministically.
5. **Guardrails**: NeMo Guardrails (input/dialog/execution rails) and Invariant Labs (deterministic rules over MCP tool-call traces, pre and post) are trace/content-pattern enforcement; only LlamaFirewall's AlignmentCheck and VIGIL's Intent Anchor reason about intent. OWASP names the control family "intent validation and goal locking at runtime" via a pre-execution Policy Enforcement Point — literally "the Intent Gate".
6. **Skill dictionary**: Voyager skill library (vector-retrieved, curriculum-grown); CoALA procedural memory; SKILL.md as the portable on-disk format (open standard Dec 2025); ExpeL/Agent Workflow Memory (insight extraction from successes AND failures, retrieved at inference); CBR for LLM agents (arXiv 2504.06943 — retrieve-adapt-reuse-retain; caveat: random exemplar sampling sometimes beats similarity retrieval — tune, don't assume). Differentiator: index NEGATIVE knowledge by intent ("this failed before", with its reconciled verdict).
7. **Memory that pushes back**: OWASP ASI06 trust-aware retrieval makes this a security control, not just an optimization; MINJA (98.2% injection success via query-only interaction) shows why passive serving is dangerous. MCP Assist's provenance/freshness/quarantine/coord_health is already the substrate; the gap is wiring it into the retrieval/acceptance path as an active critic.
8. **Cost/failure modes**: false-positive tax on easy tasks; gate-as-new-stale-authority (gate inputs must pass the same freshness/coord_health checks they enforce); clarification as injection surface; preview fidelity limited to deterministic effects; elicitation client-support variance; p95 latency budget — keep Tier 2 rare and measured.

## Novel vs. borrowable
Borrow: verify-before-commit loop; external-verifier-in-the-loop; uncertainty-gated clarification; deterministic preview; classify-then-escalate tiering; skill/case storage + intent-indexed retrieval; trust-aware retrieval framing.
Novel: (1) provenance-and-GitHub-reconciled coordination memory as the sound external verifier of the LLM-Modulo pattern — prior verifiers are symbolic planners, SMT solvers, or static policy files, never a living freshness-aware knowledge base; (2) negative-knowledge retrieval by intent as a first-class push-back signal (answers "amplifier vs. corrective" directly); (3) a skill dictionary whose entries carry claim-grade provenance/freshness/quarantine discipline, so a skill can itself be stale, tainted, or superseded.

## The tiered recommendation (as adopted by the charter)
Stage 0 deterministic pre-flight (no LLM latency) → Stage 1 memory-similarity + anti-pattern retrieval (one embedding query) → Stage 2 direct-API LLM reasoning grounded in Stage-1 results, triggered only by irreversibility, unresolved contradiction, or sub-threshold confidence. Instrument gate outcomes (approved/previewed/clarified/blocked + eventual result) to measure false-positive block rate, p50/p95 latency per tier, and retry reduction; raise the Stage-2 trigger threshold if it ever blocks valid work more than it catches errors. Do NOT build: an always-on LLM gate; anything on MCP sampling; a gate whose skill/case inputs are exempt from freshness/coord_health.
